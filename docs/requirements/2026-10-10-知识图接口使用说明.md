# 面试知识图接口：调用与增量整理

内容划分与笔记维护统一遵循 [知识库笔记与节点维护规范](../../KNOWLEDGE_STANDARD.md)。
旧标题索引只是可定位候选，不应把所有标题自动当作正式知识点；上位和原子知识均可登记。
正文结构与图关系通过稳定知识引用对应；知识身份、图身份、正文组织容器在职责上分开。
维护归属转交及统一知识定位是规范目标，现有接口兼容方式与限制见规范第 10 节。

2026-10-10：已实现服务接口、MCP 工具、页面 API 和浏览入口。
接口适用任意项目；本轮没有自动导入性能监控复盘报告。

## 登记流程

1. resolve_review_mentions 给出名称、别名、上下文，找已有知识候选。
2. AI 判断复用或少量补写，不确定的名称先建 knowledge 占位。
3. commit_review_map 一次保存模块、流程、知识引用、关系和诊断。
4. record_review_assessment 记录摸底或用户确认；实际复述才传 recall_results。
5. 页面与讲解 AI 共用 get_review_map/get_review_node。

正文通过原 append_knowledge 追加，然后设置 content_ref；也可在节点里传 content，
服务将它追加到原知识块存储，图只保存入口。修订追加记录，省略字段保留旧值。
稳定 request_id 防重；修订使用新 request_id 和既有节点 ID。
相同 request_id 如果内容不同，会返回冲突以避免误吞修订。
登记时不以节点中的 mastery/learning_status 覆盖判断，请通过评估接口记录。
证据状态、来源和可行性可省略，不作为登记门槛。

## 最小登记

```json
{
  "request_id": "cache-plan-001",
  "project_id": "my-project",
  "nodes": [
    {"id": "my-project", "kind": "project", "title": "我的项目"},
    {"client_key": "cache", "kind": "module", "title": "最新状态缓存"},
    {"client_key": "read", "kind": "flow", "title": "查询当前状态",
     "summary": "查找目标状态，复制结果，再交给响应构造。", "domains": ["cpp"]},
    {"client_key": "locking", "kind": "knowledge", "title": "共享状态的并发保护",
     "domains": ["cpp", "os"]}
  ],
  "edges": [
    {"from": "my-project", "to": "cache", "relation": "contains"},
    {"from": "cache", "to": "read", "relation": "contains"},
    {"from": "read", "to": "locking", "relation": "uses",
     "usage": "保护查询与覆盖写入的并发访问。", "required_depth": "mechanism"}
  ]
}
```

查到既有 kp-* 时，直接把 locking 换成该 ID，省略新知识节点。
回执 id_map 给出 client_key 的持久 ID；修订、评估使用持久 ID。

## 字段约定

- kind：project/module/flow/knowledge/option/claim。
- content_ref：{type:knowledge_point/knowledge_block/review_item/source_anchor/lesson,id}。
  source_anchor 还需 anchor；review_item.id 是旧复习项数值 ID。
- domains：cpp/network/os/database/algorithms/agent 等自由领域标签。
- presentation：core/followup/extension（核心回答、追问、扩展）。
- provenance/revision_note：口述、文档补充、讨论修正及原因的可选记录。
- evidence_status/feasibility/sources：可选后台信息。
- relation：contains/uses/requires/next/fails_to/supports/alternative_to/upgrade_to/
  abstracts_to/analogous_to。流程、公共知识均可以有子结构。
- context_project_id：省略采用本次 project_id；显式 null 表示公共关系。
- inclusion：core/extension，扩展默认不进入核心查询和复习范围。
- used_parts：实际使用的目标子节点 ID 或 {node_id,anchor}；纯 {anchor} 仅记录正文范围。
- required_depth：concept/mechanism/implementation_tradeoff，与当前掌握独立。
- legacy_bindings：{type:review_point,course_id,id:"T02",node_id:"kp-…"}。
  旧点号必须带 course_id，不能跨课程仅按 T02 合并。

## 查询与页面

- get_review_map(project_id=…,domains=["cpp"])：项目与 C++ 的交集。
- get_review_map(domains=["cpp"],learning_status="learned")：已学的 C++。
- include_extensions=true：展示竞品、升级、推广。
- dependency_expansion=reference/used_parts/full：关联入口、实际涉及子项、完整依赖树。
  必学范围独立于显示，始终由核心关系和明确 used_parts 决定。
- get_review_node(node_id,include_content=true)：单点正文、掌握、排期；context_edge_id
  可读取在该项目使用关系上的独立掌握判断。
- get_knowledge_point 原接口新增 review_connections，反查使用位置。
- review_graph_today：按规范知识点去重复习卡，保留旧日期，明确未学的排除。

页面 /review-map.html，学习首页和知识库都有「面试知识图」入口。
结果 cursor/limit 分页；页面最多绘制300点，按项目/领域缩小范围。
MCP/服务默认20点摘要；页面显式请求100点。单点正文和后台来源按需读取。
既有课程层级与块内标题可直接查询，无需全部迁移。新项目关系通过提交建立；
不会自动推断源码调用关系或知识之间的语义关联。

## 掌握与复述

```json
{
  "request_id": "assessment-001",
  "assessments": [
    {"node_id": "kp-…", "mastery": "usable", "learning_status": "learned",
     "basis": "user_report", "gap_note": ""}
  ]
}
```

mastery：unassessed/weak/usable/solid。
learning_status：unknown/not_started/learning/learned。
context_edge_id 可记录项目用法的掌握，公共原理判断独立。
旧记录保持 unknown/unassessed，不因正文存在认定已学或掌握。

实际复述另给 recall_results:[{node_id,result:correct/partial/wrong,hint_level?,note?}]。
复用原1/2/4/7/15/30天算法，仅更新 mastery 不改排期。
没有排期的知识点，第一次实际复述才建立排期。多个旧排期绑定同一点时，
默认选较早到期项，回执返回选定 review_item_id，其它历史保持。
新知识正文从 get_review_node 读取，原 prepare_review 沿用旧来源读取。

question_links 使用题库全局 question_id，保留 normal/firsthand。
只有报告局部题号时提供 source_ref/local_label，保存待关联项，不编题干。
一道题可关联多个节点，判断只更新 assessments 明确指定的点。

## HTTP 入口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/review_map | 摘要图与筛选 |
| GET | /api/review_node?id=…&content=1 | 单点内容、掌握、排期 |
| GET | /api/review_graph_today | 去重后的复习卡 |
| POST | /api/resolve_review_mentions | 检索复用候选 |
| POST | /api/review_map | 登记/增量修订 |
| POST | /api/review_assessment | 摸底与实际复述 |

GET domains 用逗号分隔，include_extensions 用1/0；POST 使用上述JSON。
MCP 新工具随插件服务进程重新加载生效，列表及写回不装配全量正文/聊天历史。
