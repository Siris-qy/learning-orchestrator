# LO 0.2：统一操作、内容发布与独立工作区

2026-10-16。此文描述接入方式和目录，不作为整体重构完成报告。
唯一调用规范见[LO接口使用规范](LO接口使用规范.md)。旧内容整理进度单列；新接口不会自动补齐原来只有摘要的节点。

## 使用路径

用户主要入口是 `/workflows.html`：生成教案、学习记录登记、笔记生成、知识点关联四类工作。接口仍按明确 operation 交接，八环节是内部能力分类。看板保存项目控制字段和可复用约束，通过文档库选材料，缺项先澄清；任务可存档，之后恢复原 ticket 接回外部 AI 的产物。具体字段和端口见唯一规范第10—12节。

目录补充：`workflow_board.py` 管配置、约束模块与交接任务快照；`documents.py` 管新材料的工作区文件版本和已有正式入口投影；`flow_steps.py` 管步骤图与逐步知识/题目读取。新导入文件在工作区 `documents/<kind>/`，配置、版本和任务元数据在该工作区数据库，分发包不带用户文档。前端新增 `workflows.html/js/css` 与 `flow-steps.css`，不需要前端构建服务。

选定课程或项目范围 → 生成自包含教案 → 交给网页AI学习 → 回收聊天/TXT、递归追问和确认 → 续接学习。稳定解释可以发布成正式笔记。复盘从实际答过的原面经题进入，导出项目背景和原题，讨论后回收回答、缺口，再从同一批次继续。

八个环节是分类。get_workflow_contract(operation?)查询具体操作；prepare_workflow(operation=...)准备，commit_workflow提交。操作契约在operation_contracts.py，业务适配在operation_handlers.py，旧stage翻译在workflow_compat.py。下表是历史stage的兼容格式，不推荐新调用继续用字段猜操作。

| stage | scope与artifact | 复用/接入 |
| --- | --- | --- |
| plan | course_id、section_id；milestones或curriculum | 原教学计划；新课程/项目登记 |
| context | node_ids与材料；有来源的摘录和缺口 | 选定节点的材料包，不自动成为正式知识 |
| lesson | project/course、node_ids、可选teaching_item_id；documents | 原节点/教学项教案；正式项目节点教案 |
| record | 学习course/section或复盘batch；记录增量分析 | 原教学记录或原题实际作答、追问与确认 |
| assessment | 实际覆盖范围；assessments/recall_results | 原评估和知识点排期 |
| note | 目标节点与材料；documents、可选edges/question_links | 原知识块正文、原子定位和图引用 |
| organize | 现有候选；图增量或question_entries | 原图或题目增量提交 |
| review | batch_id、可选project_id；title、items | 原题批次及范围引用 |

```python
job = lo.prepare_workflow(
    operation="note.publish",
    scope={"profile": "project", "project_id": project_id, "node_ids": [flow_id]},
    inputs={"goal": "沿一次请求复述模块", "materials": selected_materials})
# 由当前AI、skill或其他生成器写出正文。
artifact = {"documents": [{"node_id": flow_id, "body": complete_markdown}]}
receipt = lo.commit_workflow(request_id="publication-r1", ticket=job["ticket"], artifact=artifact)
```

profile可以明确选择project/course；内容准备也能根据登记类型选择默认策略。小教案数量随内容安排，同一section可通过不同teaching_item_id保留多份分段教案。课程并不要求项目骨架。

## 正文和身份

沿用已有node_id、question_id、教学项和旧绑定。节点通过content_ref定位正文；页面、复习取材和外部包共同使用content.resolve，摘要只负责导航。

prepare_content_task返回选定目标的正文版本、材料和一套策略。commit_content_task协调正文、索引、图引用及可选题目关联，保存后读回。相同request_id重放复用回执；准备后正文发生变化会提示重新读取，避免旧全文覆盖别人新增内容。没有合入的旧增量仍保留，明确covered_entry_ids后才算整合。

Markdown是编辑与交付源，SQLite最新synthesis是座舱当前正式入口。修改文件后需要重新发布，不让文件与数据库分别决定当前正文。原资料、增量和旧版本保留。

relocate_node_content(request_id,node_id,target_ref,owner_ref?)切换已准备好的正文位置和维护归属，保留图边、题目和排期的节点身份。旧原子索引通过显式绑定找到新正文。普通标题不会因此自动变为规范知识，复杂拆合仍需整理者确认边界。

## 题目与外部复盘

commit_question_batch按entries增量提交：已有题给question_id，新题给stem/client_key；可以追加问法、来源、分类、知识关联和pending_reason，修改原文使用明确的corrections。省略保留已有字段。语义查重由AI完成，程序不凭标题相似自动合并。普通/亲历等级独立于掌握。图题关联支持action=unlink纠正某个位置而保留题目本身。

save_review_batch保存已有题的顺序、原编号和本批所需节点。list_review_batches随时可找回，不受未到期限制。页面是/review-batches.html，项目页有按项目筛选的入口。

export_review_batch返回自包含Markdown和manifest。正文从正式入口读取，清单保留题目身份和正文版本；默认不带参考答案。缺少的正式背景列在missing_content，方便补齐。

prepare_review_record返回TXT未处理增量、原题清单及遗留问题。没有编号也由AI按题意匹配；不确定的片段放unmatched，后来明确后可标resolved。commit_review_record一次提交：

```json
{
  "request_id": "external-round-2",
  "batch_id": "my-interview-batch",
  "attempts": [{"question_id":"original-question","kind":"answer","text":"用户实际回答","result":"deepen","coverage":[{"node_id":"actually-covered-node"}],"gap_note":"具体缺口"}],
  "gaps": [
    {"id":"outer","title":"调用流程","state":"open"},
    {"id":"child","parent_id":"outer","title":"响应怎样配对","state":"explained"}
  ]
}
```

answer、explanation、confirmation分别记录作答、补学讲解、用户确认。explained不等于resolved；解决子问题不会关闭父问题或并列问题。问题挂实际node_id后，详情页就地显示并链接原批次。题库详情也能找到这次判断来自哪个批次。

可选recall_results只作用于本次真实回答明确覆盖的知识，沿用原排期。局部通过不把上位主题整体标为掌握，也不清掉其他遗留问题。日期安排和主动通知是两件事；本轮提供日期/页面提示，没有新增常驻通知服务。

## 替换策略

在扩展模块的register(orch)中调用orch.register_workflow_strategy(id,operation,instructions,prepare?,transform?,profile?)，替换分析方法、材料选择和产物加工。策略登记只作用于这个Orchestrator/工作区。模块级旧register_strategy仅保留启动模板兼容，不作为运行中扩展方法。lo.json的strategy_modules指定可导入模块；examples/strategy_ext.py提供示例。

skill指导AI分析与写作，prepare可以接解析/检索组件，transform可以加工产物，最终经过同一个服务适配器保存。当前任务只返回所选策略，不拼上所有规则。SKILL.md保留短路由，详细指导按备课、记录、内容、复盘或直接授课分别读取。

## 目录与新机器

| 路径 | 职责 |
| --- | --- |
| src/learning_orchestrator/service.py | 页面、MCP、脚本共用入口 |
| workflow.py / operation_contracts.py / operation_handlers.py | 操作协调、可查询契约和调用领域实现的业务适配 |
| workflow_compat.py / production.py | 旧调用转换、正文/教案生成准备与发布 |
| content.py / review_views.py | 正文定位与页面读模型 |
| review_batches.py / question_batch.py | 原题批次、实际作答、遗留问题和题目增量 |
| curricula.py / workspace.py | 课程/项目登记、配置、空库与合成演示 |
| dashboard_static | 学习、基础知识、项目、题库、已登记复盘 |
| skills/learning-orchestrator | 按任务读取的AI操作规范 |
| 工作区lo.json | 数据库、资料根、初始化类型、扩展模块 |
| 工作区data / notes / sources / exports | 运行库、笔记编辑源、原资料、外部交接快照 |
| docs/design / docs/audits | 规范及核验，不作正式知识正文 |

新机器按根README从源码安装Python 3.10+环境。workspace init --path创建空工作区，--demo加入合成请求分发项目，不加载本人资料。空库用register_curriculum登记课程/项目和章节，再接入材料和备课。旧工作区未指定workspace时继续使用原数据库。

显式db/source_roots优先；指定workspace后读取lo.json，材料路径相对工作区解析；旧模式保留数据库和资料根环境变量。源码安装使用pip install -e，保留页面与程序完整目录；本轮不是独立wheel桌面安装包。

scripts/build_release.py按白名单生成源码zip，带程序、页面、skill、安装说明和合成演示，不带个人笔记/PDF/数据库/聊天/备份。MCP配置由scripts/make_mcp_config.py按使用者本机Python生成。本轮未上传GitHub；公开发布的许可证由项目所有者确定。
